# WEPR Growth Operations

## Purpose

把渠道动作还原为能产生并交付客户价值的经营系统。先验证机会与单位经济，再设计获客、转化、交付、留存和复购；不把流量、播放量或工具数量当作商业结果。

## Principles

1. 先定义业务结果、目标客户、付费任务与约束，再选渠道。
2. 先跑通最小闭环，再复制；先人工稳定，再自动化。
3. 区分事实、假设、经验基准和待验证项。收益截图、GMV、个案和平台传闻不等于证据。
4. 每项动作必须有负责人、节奏、输入、输出、质量门槛、指标和停止条件。
5. 同时检查毛利、获客成本、履约成本、退款、库存、税费、现金流和团队容量。
6. 不伪造用户、评论、口碑、权威背书或案例，不绕过平台限制。

## Workflow

### 1. Frame the problem

先输出一页诊断：业务阶段、目标结果、客户任务、当前瓶颈、证据、关键假设、边界条件。若用户给的是渠道动作，反推它服务的业务结果。

### 2. Pass the opportunity gate

阅读 [opportunity-and-economics.md](references/opportunity-and-economics.md)。判断需求强度、支付意愿、供给优势、交付可行性和单位经济。证据不足时设计最小验证，不直接给规模化承诺。

### 3. Map the smallest closed loop

用一条链表达：`客户任务 → 价值主张/产品 → 触达 → 留资/下单 → 销售/成交 → 交付 → 留存/复购/转介绍 → 数据回流`。标出唯一主要瓶颈。阅读 [operating-system.md](references/operating-system.md)，把闭环拆成工作流、SOP、节奏、责任与质量控制。

### 4. Design channel execution

阅读 [channel-operations.md](references/channel-operations.md)，只选择与客户任务、信任机制、转化路径和交付能力匹配的渠道。输出每个渠道的角色，而非简单罗列平台。

### 5. Define measurement and experiments

阅读 [measurement-automation-and-risk.md](references/measurement-automation-and-risk.md)。建立 KPI 树、实验卡、数据口径、复盘节奏和停止/扩量规则。自动化必须有人工审核、权限边界、速率限制、日志和回滚。

### 6. Produce the deliverable

- 运营诊断：问题树、瓶颈、证据、优先级、30 天行动。
- 运营系统：闭环图、工作流、SOP、周/月节奏、RACI、仪表盘。
- 渠道计划：人群任务、内容/流量机制、转化链、预算、实验和风险。
- 客户方案：经营判断、策略主张、系统设计、阶段路线图、交付物、KPI、治理、团队和下一步决策。

制作客户演示稿时与 `$wepr-presentation-workbench` 配合；商业判断用 `$wepr-business-workbench`；营销策略用 `$wepr-marketing`；付费媒体细化用 `$wepr-advertising-workbench`；公关与舆情用 `$pr-strategy-workbench`。

## Quality Gate

- 指标连接收入、毛利、合格线索、成交、留存或交付质量，而非只有曝光。
- 每个工作流写清负责人、时间、交付物、验收标准和异常处理。
- 区分 0→1 验证、可重复增长、规模化和系统化阶段。
- 所有数字有来源、口径、日期或明确标注为假设。
- 写明停止条件、扩量条件和平台/合规边界。
- 删除夸大收益、万能公式、过时平台机制和不可验证案例。
