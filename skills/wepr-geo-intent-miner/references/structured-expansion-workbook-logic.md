# 核心词与结构化拓展逻辑

## 适用场景

用于“一个核心词配若干拓展词”、从 Excel 前后缀表拓词、批量生成候选问题、建立报价词包或监测问题库。表格、公式和已有案例均视为候选生成资料，不自动视为真实需求或平台数据。

## 两阶段模型

### 第一阶段：槽位组合，提高召回

把输入拆成五类槽位：

`范围/语境前缀 A + 属性/评价前缀 B + 核心词 C + 对象后缀 D + 决策后缀 E`

按需要生成六类基础组合：

1. `A+B+C+D`
2. `A+B+C+D+E`
3. `B+C+D`
4. `B+C+D+E`
5. `C+D`
6. `C+D+E`

再补充不适合机械拼接的自然问句，如：`C怎么选`、`C适合谁`、`C和某类替代方案有什么区别`、`C有哪些风险`。组合数量只是候选池规模，不是正式词库数量。

### 第二阶段：语义资格审查，提高精度

候选词逐条通过以下质量门：

1. **词根完整性：** 用户要求“完整包含核心词”时，用完全一致的核心词字符串检查；不得用近义词替代后声称已满足。
2. **语义独立：** 单条问题脱离上下文仍能直接向 AI 提问。
3. **自然表达：** 删除机械病句；优先使用真实口语和明确场景。
4. **业务匹配：** B2C 产品不套“源头厂家、供应商”等 B2B 词，B2B 采购也不机械套消费场景。
5. **意图区分：** 至少覆盖推荐/比较、场景、人群、参数、价格、风险、购买/实施、售后/验证中的相关类别，不用同义词重复充数。
6. **证据可答：** 问题应能映射到产品事实、标准、价格、案例、第三方评价或内容资产；无法合规回答的词降级为监测或证据补采。
7. **去重：** 合并同目标问法，只保留表达最自然、约束最清晰的代表词；固定数量用其他真实意图补足。
8. **风险检查：** “最好、权威、十大、排名”等词仅在存在公开、透明、可复核标准时进入内容生产，否则只作为用户意图或监测词。

## 核心词包设计

一个词包建议包含：`core_keyword`、`exact_match_required`、`audience_mode`、`category`、`scenario`、`decision_stage`、`expansion_question`、`slot_pattern`、`intent_type`、`evidence_need`、`content_asset`、`platform_fit`、`priority` 和 `compliance_level`。

若每个核心词至少需要 N 个拓展词，先生成约 `2N–4N` 个候选，再按质量门筛选到 N 个以上。正式输出同时报告候选数、去重数、淘汰原因、最终数和覆盖的意图类别。

## 表格实现注意

- 不使用 `PHONETIC(range)` 代替字符串拼接。
- 优先使用 `TEXTJOIN("",TRUE,...)`、`CONCAT(...)` 或由程序显式连接非空槽位，并保留组合来源列。
- 主词/词根列每行显式填充，或可靠引用固定核心词单元格。
- 输出区与槽位词典分离；保留 `valid`、`reject_reason`、`duplicate_group`、`exact_core_match` 等质检列。
- 公式结果仍需人工或语义模型审核，不能视为真实搜索需求。

## 验收清单

- 每个核心词的最终拓展数量达到要求。
- 需要完整包含时，所有拓展均通过精确字符串检查。
- 每条问题自然、独立、业务对象正确。
- 没有靠同义变体或轻微词序变化凑数。
- 每个问题有意图、场景、证据和资产映射；高风险绝对化词已标记。
- 未把组合数量、案例结果或表格输出冒充搜索量、AI 热度或真实用户频次。
