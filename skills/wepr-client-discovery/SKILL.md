# WEPR 客户需求澄清工作台

把“客户想做点什么”推进到“团队知道为什么做、为谁做、解决什么、如何判断完成”。事实由研究补，选择由有决策权的人做。

## 路由

- 实时访谈或启动会：读取 [references/interview.md](references/interview.md)。
- 需要客户、销售、产品或法务异步补充信息：读取 [references/questionnaire.md](references/questionnaire.md)。
- 把现有对话、会议纪要或资料整理为 brief：读取 [references/brief-and-handoff.md](references/brief-and-handoff.md)。
- 涉及多人冲突、审批链和悬而未决事项：读取 [references/decision-map.md](references/decision-map.md)。

## 核心流程

1. 明确本轮需要解锁的决定、最终交付物、使用者、截止时间和决策人。
2. 建立已知清单：事实、客户原话、现有数据、已作决定、限制条件和不可变项。
3. 建立问题前沿：只保留会改变方向、范围、报价、内容或验收的未知项。
4. 按决策树逐轮提问。每轮聚焦一个主题，先复述已确认内容，再处理下一个分支。
5. 将回答标为事实、偏好、决定、假设、冲突或待验证项；记录决定人和截止时间。
6. 当所有关键分支已关闭或明确分配责任后，输出可交接需求简报，并路由到对应专项技能。

## 提问纪律

- 先问会改变方案的高杠杆问题，不按固定问卷机械走完。
- 一次只处理少量相关问题，让回答者知道每个问题为什么重要。
- 可通过公开资料、数据或现有文件查到的事实由执行者研究，不把检索工作推给客户。
- 客户独有的目标、取舍、风险容忍、审批和资源限制必须由客户确认。
- 接受“不知道”。将其转换为研究任务、实验、默认假设或负责人，而不是逼出伪答案。
- 发现术语含义不同，立即建立共同定义；不要让同一个词在方案中承担多个意思。
- 不在访谈中偷偷出售既定方案。问题应帮助决策，不应诱导客户同意预设结论。

## 完成门槛

只有以下内容均明确，才能把需求标为“可进入方案”：

- 业务目标、目标受众和优先问题；
- 期望行为或业务结果，以及当前基线；
- 范围内、范围外、预算、周期和资源；
- 可公开证据、证据缺口和必须核验的主张；
- 决策人、参与人、审批顺序和反馈时限；
- 交付物、格式、验收标准、风险边界和下一步。

未达到门槛时输出“暂定 brief”，明确阻塞项和默认假设，不假装需求已经完整。

## 输出

- 客户需求简报；
- 决策树与问题前沿；
- 异步问卷；
- 会议结论、未决项、负责人和期限；
- 项目交接文档；
- 专项技能路由建议。
